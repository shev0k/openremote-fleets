## Entry points

- route: `/`
- page: `src/app/pages/LiveFleet.tsx`
- shell: `src/app/features/live-fleet/components/LiveFleetPageShell.tsx`
- provider: `src/app/features/live-fleet/providers/LiveFleetWorkspaceProvider.tsx`

`LiveFleet.tsx` is intentionally thin. Most state is owned by `LiveFleetWorkspaceProvider`, which splits values into smaller contexts for data, selection, playback, preferences, and layout.

Important provider hooks:

- `useLiveFleetData` loads vehicles and handles route-backed simulation inputs.
- `useLiveFleetSelection` owns selected vehicle, details, and selected-route loading.
- `useLiveFleetRoutes` owns current route, historical route, active segment, graph overlay segment, and playback controller.
- `useLiveFleetSimulation` moves mock vehicles along playback routes when mock mode supports it.
- `useLiveFleetRealModeRefresh` refreshes real-mode fleet and route data while avoiding playback/scrub conflicts.
- `useLiveFleetWidgetLayoutState` stores sidebar widget layout and visibility.
- `useLiveFleetOverlayState` manages quick panels, active vehicle overlay, and pinned vehicle overlays.

## Vehicle display status

Display status and marker status are different on purpose.

<VehicleStatusBadgeExample />

Display badges come from `src/app/components/map/vehicleDisplayStatus.tsx`. They are used in lists, overlays, and compact summaries. Alerting wins when `status === "alerting"` or `activeAlertCount > 0`. Explicit offline stays offline. Idling, parked, and stationary stay distinct. Everything else becomes moving.

Marker status comes from `src/app/components/map/vehicleMapMarkerStatus.ts`. It adds map-only states such as `driverBreak`, `signalDegraded`, and `stopped`. Signal degraded is based on GSM, GNSS status, HDOP, and satellite count.

## Real vs mock behavior

In real mode, the workspace reads through repositories backed by OpenRemote services and mappers. Partial backend failures should return safe empty values instead of breaking the page.

In mock mode, vehicles come from fixtures and `MockLiveFleetSimulationService` can animate vehicle positions from playback routes. Mock data should stay aligned with the Teltonika catalog so the UI is still a useful proxy for real tracker data.

## Maintenance notes

- Keep map helper code in `src/app/components/map` when it is shared by Live Fleet, Route Playback, or Wall Display.
- Keep subscriptions, polling, intervals, and animation frames out of render-heavy components.
- Guard async responses so a slow vehicle-detail request cannot overwrite a newer selected vehicle.
- Keep route, timeline, selected segment, and map focus synchronized.
- Add tests around state hooks, status rules, route behavior, and widget storage when changing workspace logic.
